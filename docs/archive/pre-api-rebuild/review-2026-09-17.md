# Repo review — 2026-09-17

Full-repo scan of the Phase 1 platform (API, frontend, infra, docs). Findings are ranked by what
actually bites, not by how easy they are to fix. Every line/symbol reference was verified against the
tree at `c3fa049`+ (branch `refactor/capability-middleware`).

**Not listed:** anything the roadmap or a checklist openly defers — hierarchy + `tenant_visibility_grants`,
component 08 billing, the audit read API, impersonation, `/bootstrap`, the first-run wizard. Those are
decisions, not gaps.

Items marked **(self-inflicted)** were introduced during the 2026-09-14…17 sessions. They are listed
first within their severity band because they are the freshest and the cheapest to undo.

**Status (2026-09-18):** P0 (1–4) and P1 (5–15) are closed on `fix/review-p0-p1`; each carries a
**Fixed** line naming the commit. P2 (16–25) and P3 are open. The `docs/` drift in P3 is partly
addressed already — the SRS lines each fix contradicted were corrected in the same commit — but the
six 🟡 In Review files and `conventions.md`'s `name_dv`/`deleted_at` mandate are untouched.

## P0 — fix before anything else is built on top

### 1. Suspending a tenant does not suspend anything
- **Where:** `apps/api/internal/tenancy/lifecycle.go:83`, `apps/api/internal/auth/kratos.go`,
  `apps/api/internal/httpapi/router.go:72`
- **What:** `SuspendTenant` writes a status column and an audit row. Nothing enforces the result.
  `tenancy.Middleware.RequireTenant` — which rejects non-active tenants and checks membership — is
  implemented but **mounted on no route**. The Kratos client has no session-revocation method at all.
- **Why it matters:** FR-TEN-03, FR-AUTH-09/10, FR-MEM-05 and UC-AUTH-11 all require revocation, and
  02 is marked 🟢 Confirmed. A suspended tenant's users keep working sessions until they expire (12h).
  Prompt access revocation is a stated requirement for this client base, not a nice-to-have.
- **Do:** add `DeleteIdentitySessions` to the Kratos client and call it inside the suspend
  transaction; mount `RequireTenant` on tenant-scoped routes. Until both exist, mark FR-TEN-03 unmet.
- **Fixed:** 5b19a33 — `RequireTenant` now guards every mounted route, with a route audit that fails
  if a new one escapes it. Sessions are deliberately *not* revoked (a Kratos session belongs to an
  identity, not a tenant); a 403 carrying `tenant_suspended`/`tenant_archived` replaces it, and the
  SRS was corrected to match.

### 2. RLS isolation is unproven on the tables that decide permissions
- **Where:** `apps/api/internal/db/sqlc/authorization_integration_test.go` (all tests),
  `apps/api/internal/dbtest/dbtest.go:112`
- **What:** every authorization test runs through `env.Tx` — the owner/superuser role, which bypasses
  RLS unconditionally. `dbtest.AppTx` exists and is documented *specifically* for proving enforcement,
  and is used by exactly one test (`audit_integration_test.go`).
- **Why it matters:** `user_roles` decides capabilities. A broken policy there is silent cross-tenant
  privilege escalation **with a fully green suite**.
- **Do:** an `AppTx`-based isolation test per RLS'd table: write as tenant A, assert invisible as B.
- **Fixed:** 4e92834 — an `AppTx` isolation test per table, each checked three ways (`USING`, `WITH
  CHECK`, own-row visibility), and verified to fail when run through `env.Tx`.

### 3. The RLS coverage guard doesn't check what it's documented to check
- **Where:** `apps/api/internal/tenancy/rls.go:72`, `.claude/rules/tenancy.md:49`,
  `docs/srs/phase-1/01-platform-foundation/use-cases.md:53`
- **What:** UC-FND-06 says the guard verifies FORCE RLS + a policy + **the `tenant_id` column
  default**. It verifies the first two. Separately, only `audit_log` actually *has* that default —
  `user_roles`, `role_requests`, `support_access_grants` are plain `NOT NULL`
  (`00008_authorization.sql:124,144,176`).
- **Why it matters:** the default is what makes it impossible for a query to forget `tenant_id`.
  A policy that never references `tenant_id` passes the guard today.
- **Do:** add the default to the three tables; extend the guard to assert it, and to assert the
  policy actually references `tenant_id`.
- **Fixed:** 55ceea7 — the guard now requires the `tenant_id` default; the three tables that never
  had one were fixed in the original migration.

### 4. **(self-inflicted)** Owner email is written to the logs
- **Where:** `apps/api/internal/tenancy/provision.go:98`
- **What:** the orphaned-identity error logs `owner_email`. The redaction handler
  (`observability/logging.go:100`) covers credential-shaped keys only — `email`, `phone`, `name`
  pass through.
- **Why it matters:** FR-OBS-06 forbids PII beyond IDs, and 07's use-cases call a redaction miss
  "a bug + test failure". The Kratos identity id already identifies the row an operator must clean up.
- **Do:** drop the field. Consider adding `email`/`phone` to the redaction list as a backstop.
- **Fixed:** 5b19a33 — the address is out of the provisioning error log. The suggested
  redaction-list backstop was not added: blanket-redacting `email`/`phone` broke an existing test
  that asserts a legitimate field survives, so keeping PII out stays a per-call-site decision.

## P1 — security and correctness

### 5. Any internal-tenant member can enumerate every customer
- **Where:** `docker/cerbos/policies/resource_tenant.yaml`
- **What:** `list`/`get` allow the `operator` derived role with **no capability condition**, while
  provision/suspend require one. Membership of the internal tenant alone yields the full tenant
  directory. Irreversible `archive` is gated on `platform:tenants:suspend`; no archive capability
  exists in `internal/auth/capabilities.go`.
- **Do:** add `platform:tenants:read` and `platform:tenants:archive`; condition every action.
- **Fixed:** b219019 — `list` and `get` now require `platform:tenants:read`.

### 6. `platform:*` is a literal string, not a wildcard
- **Where:** `docker/cerbos/policies/resource_tenant.yaml:22`, `apps/api/internal/auth/cerbos.go:96`
- **What:** policies test `"platform:*" in request.principal.roles`. It matches only a role that
  literally grants the slug `platform:*`; `platform:tenants:archive` matches nothing. This is why
  item 5's archive ended up on the wrong capability.
- **Do:** either grant `platform:*` explicitly as a super-capability and document it as a literal,
  or switch the policies to a prefix match over the capability list.
- **Fixed:** b219019 — written down in the policy, the capability catalog and FR-AUTHZ-02's list.

### 7. `tree_key` allocation is a lost-update race
- **Where:** `apps/api/internal/db/query/tenancy.sql:48`, `apps/api/internal/tenancy/provision.go:22`
- **What:** `SELECT MAX(tree_key)+1` under READ COMMITTED with no lock. Concurrent provisions compute
  the same key; one dies on `tenants_tree_key_key`, which isn't mapped in `uniqueViolationField`, so a
  legitimate request gets a bare 500.
- **Do:** allocate from a locked counter row — the pattern `tenancy.md` already mandates for gapless
  document numbering — or `pg_advisory_xact_lock`.
- **Fixed:** 4858656 — `tenant_tree_key_seq`, allocated by a column default, so callers outside a
  transaction (`provision-dev`) are covered too.

### 8. Nested `WithTenant` rewrites the outer transaction's tenant
- **Where:** `apps/api/internal/rls/rls.go:28`
- **What:** `set_config(…, true)` is transaction-scoped, not savepoint-scoped. pgx implements a nested
  `Begin` as a SAVEPOINT, so an inner `WithTenant(tx, B)` leaves `app.current_tenant = B` for the
  remainder of the outer transaction.
- **Why it matters:** not reachable today (callers pass the pool), but `auth.DBTX` now accepts a `Tx`,
  so the signature invites it. First call inside another tenant's scope is a live cross-tenant leak.
- **Do:** save and restore the prior value, or detect and reject nesting.
- **Fixed:** 20953c1 — the enclosing scope is captured and restored before the savepoint is
  released.

### 9. No `Origin` validation, with a parent-domain session cookie
- **Where:** `docker/kratos/kratos.yml:86`, `apps/api/internal/httpapi/router.go`
- **What:** the cookie is scoped `.bool.test` so it works across tenant subdomains (by design).
  `SameSite=Lax` separates external sites but **not sibling subdomains**, and the API validates no
  `Origin`/`Referer` — verified: a request bearing `Origin: http://evil.bool.test` is served 200.
- **Why it matters:** exploitable the moment any `*.bool.test` host serves attacker-influenced
  content (uploads, tenant branding, an XSS in the tenant SPA). An operator's session is the prize.
- **Do:** reject mutating requests whose `Origin` isn't an expected host.
- **Fixed:** 20953c1 — `httpapi.RequireSameOrigin` at the root; unsafe methods only, missing
  `Origin` allowed, hosts compared without the scheme (TLS terminates at the proxy).

### 10. **(self-inflicted)** Every authenticated request performs a write
- **Where:** `apps/api/internal/auth/middleware.go:57`, `apps/api/internal/db/query/users.sql:14`
- **What:** `SyncUserOnLogin` is an `UPDATE … last_login_at = now()` executed on every `/v1/*`
  request, including `GET /me`.
- **Why it matters:** takes a row lock per request (serialising a user's concurrent calls), produces
  a dead tuple per request, and makes the API unable to serve reads from a replica.
- **Do:** admission is a read — `SELECT` it. Write `last_login_at` conditionally (or from a Kratos
  login hook).
- **Fixed:** c678d55 — admission is a `SELECT`; the write survives only for drifted Kratos traits or
  a login stamp older than five minutes.

### 11. **(self-inflicted)** Inbound `X-Request-Id` is trusted and persisted
- **Where:** `apps/api/internal/httpapi/router.go:47`, `apps/api/internal/audit/audit.go:38`
- **What:** chi adopts the caller's header verbatim and it is written to `audit_log.request_id` —
  unbounded, attacker-chosen, collidable with another request's id.
- **Do:** accept an inbound id only against a strict pattern and length cap; otherwise generate.
- **Fixed:** c678d55 — implausible values are dropped before chi adopts them, so interoperability
  survives and forgery doesn't.

### 12. **(self-inflicted)** The "blanket" body cap isn't blanket
- **Where:** `apps/api/internal/httpapi/sanitize.go:42`
- **What:** the middleware returns *before* `MaxBytesReader` for multipart/octet-stream/image/video/
  audio — exactly the bodies most worth capping. The comment at `:12` claims the opposite.
- **Do:** apply the cap first, then decide whether to inspect the body.
- **Fixed:** c678d55 — capped either way, at two sizes: one small enough to buffer, one generous
  enough for a real upload.

### 13. `erp_app` holds UPDATE/DELETE on `audit_log`
- **Where:** `apps/api/internal/db/migrations/00002_app_role.sql:21`, `00009_audit.sql:39`
- **What:** the append-only trigger is the only guard; the grant is still there. TRUNCATE is also
  uncovered (mitigated only incidentally, by not being granted).
- **Do:** `REVOKE UPDATE, DELETE ON audit_log FROM erp_app`, and add a statement-level TRUNCATE guard.
- **Fixed:** 4858656 — `REVOKE UPDATE, DELETE, TRUNCATE` plus a statement-level TRUNCATE trigger.
  The test was passing vacuously (an aborted transaction fails everything after the first refusal)
  and now runs each attempt in its own savepoint.

### 14. A database outage reports as "tenant not found"
- **Where:** `apps/api/internal/tenancy/middleware.go:39`
- **What:** every `GetTenantBySlug` error maps to 404. The membership check below it gets this right.
- **Do:** distinguish `pgx.ErrNoRows` from everything else, as the rest of the codebase now does.
- **Fixed:** 5b19a33 — `pgx.ErrNoRows` is distinguished from everything else.

### 15. No config validation — production can boot on dev credentials
- **Where:** `apps/api/internal/config/config.go`
- **What:** `APP_DSN` defaults to `erp_app:erp_app@postgres`. A deploy missing the variable starts
  successfully against the dev default rather than failing.
- **Do:** require DSN/Kratos/Cerbos URLs with no defaults outside dev; fail fast at startup.
- **Fixed:** 20953c1, 4204756 — validation with no defaults outside dev, then every value moved into
  `.env.example` so nothing in the repo supplies one at all.

## P2 — foundations that get more expensive every week

### 16. There is no API contract
- **Where:** `packages/api-client/` (empty), `apps/admin/src/features/tenants/types.ts:1`
- **What:** no OpenAPI spec exists. The only Go↔TS link is a hand-copy commented "Mirrors
  httpapi.tenantResponse". Rename a JSON field and Go tests, typecheck, and CI all stay green while
  the column renders blank.
- **Do:** generate the spec from the handlers, emit `packages/api-client`, add a CI step that fails
  if regeneration produces a diff.

### 17. The coverage gate is fiction
- **Where:** `.claude/rules/testing.md`, `.github/workflows/ci.yml`, `compose.yaml:208`
- **What:** the rules demand 100% Vitest on `components/**` and `lib/**` and 100% Go coverage,
  enforced in CI. There is no Vitest anywhere — no config, no dependency, no test files — and Go runs
  without `-cover`. CI never mentions coverage, never runs `turbo run lint`, and its matrix skips
  `apps/website` entirely.
- **Why it matters:** a documented gate nobody enforces is worse than none, because it is trusted.
- **Do:** implement it, or amend `testing.md` to state the real bar. Not both halves of a lie.

### 18. e2e never exercises credential entry, and nothing covers the negative paths
- **Where:** `e2e/tests/*.spec.ts`, `apps/app/src/routes/login.tsx:68`
- **What:** the real Kratos flow *is* driven (flow fetch, CSRF, submit, cookie, redirect), but the
  credentials come from `autofill={import.meta.env.DEV && …}` — compiled out of production. The suite
  would fail against a production build. Nothing covers wrong password, `aal2`/MFA, recovery,
  verification, or logout, while component 02 is 🟢 Confirmed.
- **Do:** type credentials explicitly; run e2e against the production build; add the negative paths.

### 19. "One `compose up`" is not true
- **Where:** `compose.yaml:446`, `e2e/run.sh:13`, `.github/workflows/ci.yml:55`
- **What:** `proxy` is an **external** network and Traefik lives outside the repo — CI hand-builds
  both. On a fresh box `docker compose up` fails. There is no root `README.md` and no install doc.
  This contradicts UC-FND-08 and the self-host promise that drives the whole architecture.
- **Do:** keep this as `compose.dev.yaml`; add a self-host compose bundling its own proxy + TLS, and
  a short install README.

### 20. The only compose is dev-shaped
- **Where:** `compose.yaml`, `docker/kratos/kratos.yml:107`
- **What:** Kratos cookie/cipher secrets committed to git, HIBP disabled, `--dev` on, Kratos DSN
  hardcoded with **owner** credentials and `sslmode=disable`, Grafana published with anonymous-Admin
  and its login form disabled, Loki/Tempo/Prometheus/Promtail all published, everything on `web`
  (no TLS, so the session cookie is never `Secure`). No resource limits, restart policies or
  `cap_drop`. FR-FND-12 promises dev + prod overlays; only dev exists.
- **Do:** treat every one of these as a production blocker, tracked before the first real deployment.

### 21. Redis runs and does nothing; there is no rate limiting
- **Where:** `compose.yaml`, `apps/api/internal/config/config.go:24`
- **What:** configured as "the cache + rate-limit backend", referenced nowhere else. No client, no
  cache, no rate limiting anywhere in the API, not even a `/readyz` check.
- **Do:** wire rate limiting on the auth-adjacent paths, or drop the service until it earns its place.

### 22. `sqlc` generation is unpinned and unscripted
- **Where:** nowhere — that's the finding
- **What:** generated code is committed, but no Makefile target, CI step, or pinned version exists.
  Generation depends on whatever a developer types; a `:latest` invocation silently bumped the
  generator across every generated file during this review.
- **Do:** pin the version and script it; have CI fail if regeneration produces a diff.

### 23. `ListTenants` is unbounded and shaped to stay that way
- **Where:** `apps/api/internal/db/query/tenancy.sql:24`, `apps/api/internal/tenancy/routes.go`
- **What:** no `LIMIT`, no index on `created_at`, and the handler returns a bare JSON array — so
  adding pagination later is a client-breaking change. It is also the template every future list
  endpoint will copy, including tenant-scoped business data that won't be bounded.
- **Do:** keyset pagination and a response envelope now, while there is one consumer.

### 24. Observability runs but isn't usable
- **Where:** `docker/grafana/provisioning/`, `docker/prometheus/prometheus.yml`, `docker/loki/loki.yml`
- **What:** datasources only — no dashboards, no alert rules, no `rule_files`. Loki sets
  `retention_period` with no compactor, so nothing is ever deleted; Tempo has no retention. Component
  07 is marked ✅ Implemented.
- **Do:** one dashboard and one alert that would actually page someone; fix the retention configs.

### 25. Backup and restore appear nowhere
- **Where:** `docs/` — absent except an aside in `adr/0001`
- **What:** for a client base where the Auditor-General is a stakeholder and audit retention is
  claimed at ≥7 years, there is no backup, restore, or per-tenant export/erasure story.
- **Do:** write it down before the first production tenant, not after.

## P3 — docs and code disagree

The repo's own rules make `docs/` authoritative and require docs to be fixed *first*. These are the
places that didn't happen. Several were caused by this week's refactors.

- **Six of seven SRS files say 🟡 In Review** while their checklists say Implemented — code shipped
  ahead of the Idea→Expansion→Review gate. This is the root cause of item 1 being "Confirmed" but absent.
- **`conventions.md` contradicts the entire schema** (`:100`, `:104`): it mandates paired `name`/`name_dv`
  columns and `deleted_at` soft deletes. Every table uses `name_i18n jsonb`, and no table has
  `deleted_at` — lifecycle is `active_from`/`active_to`. `DB-FOUNDATION.md:328` records the
  2026-09-11 revision; the rules file never caught up.
- **Docs cite symbols that no longer exist:** `httpapi.AdminRoute` and `/api/v1/admin/tenants` in
  `05/checklist.md`, `04/checklist.md` and `docker/cerbos/policies/resource_tenant.yaml:4`. The routes
  are `/api/v1/tenants`, enforced by `auth.OperatorsOnly` + `auth.RequirePermission`.
- ~~**Two comments still describe JIT-upsert**~~ — fixed. `auth/middleware.go:16` was corrected in
  c678d55; `00005_identity.sql:5` now states that sign-in verifies the row and never creates it.
- **Undocumented behaviour:** root-level body sanitising (1 MiB cap + whitespace trimming of every
  JSON string), the `X-Request-Id` response echo, the per-request access log, `/` answering readiness,
  and the synthetic `"collection"` resource id. Sensible, but no FR describes any of it.
- **Boot sequence omits two of its six documented steps** (UC-FND-01): no migration-version check, no
  idempotent reference-data seeder.
- **Audit payloads aren't the documented shape** — FR-AUD-03 specifies changed-column diff plus full
  snapshot on create/delete; provisioning records `{after:{slug,status}}`.
- **The RLS guard exempts three tenant-owned tables** (`tenant_apps`, `tenant_settings`, `user_apps`)
  as a pragmatic escape hatch no SRS mentions. They are described in the same file as dead schema —
  drop them rather than carry the exemption.
- **`00008_authorization.sql:3` declares its tables outside the RLS regime**, then `00010` puts FORCE
  RLS on three of them. `tenancy.md`'s platform/business split has no category for these.
- **An entire app-activation schema** (`apps`, `tenant_apps`, `tenant_settings`, `user_apps`,
  `roles.app_id`) exists that no SRS component owns — and it's why `roles` sits outside RLS.
